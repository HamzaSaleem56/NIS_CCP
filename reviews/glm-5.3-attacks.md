### Verified correct

1. **Known-prefix recovery math is right.** For the true rail count, `stage_one = rail_fence_decrypt(ct, R)` is the Vigenère ciphertext `V`, so `key_stream[i] = V[i] − P[i] = K[i mod L]` exactly. The periodicity check admits the true `L`, `key = key_stream[:L]` is the true key, and — provable invariant — every passing candidate's decryption reproduces the known prefix character-for-character (`decrypt[i] = stage_one[i] − key_stream[i] = known[i]` for all i < m, since the check guarantees `key[i mod L] = key_stream[i]`). The quadgram score only ranks *consistent* candidates; it cannot produce a prefix-contradicting answer.
2. **Tie-breaking is correct.** `L` and `2L` both pass periodicity and yield identical plaintext; strict `score > best.score` with ascending `key_length` keeps the **minimal period** — the canonical key.
3. **candidate_found in known mode is meaningful**: `False` ⟺ no (rails, key_length) combination consistent with the prefix exists. Genuine failure is representable.
4. IC (probability scale, matches `ENGLISH_IC=0.066`), chi-squared shift recovery (correct decrypt direction, expected counts `n·fᵢ`), and the quadgram smoothing (`(count+0.1)/(total+0.1·26⁴)`, unknown floor `log10(0.1/denominator)`) are all internally consistent. ENGLISH_FREQUENCIES has the standard 26 values in A–Z order. Early-return paths preserve invariants (elapsed set, evaluated=0, found=False). CLI catches `ValueError`/`OSError` (UnicodeDecodeError included) → `parser.error`.

### Findings

1. **MEDIUM — `candidate_found` is vacuous in frequency mode.** Any candidate of length ≥ 4 scores an average of log-probs bounded below by ≈ −5.7 (min possible `unknown = log10(0.1/45697.6)`), so the first evaluation always beats the −100.0 sentinel. For any input ≥ 4 chars the flag is **always True**, meaning "attack executed," not "plausible English found" — garbage in, `candidate_found: true` out. Known mode's flag means "prefix-consistent key exists." Same field, two meanings. Either document this, or gate frequency mode on a quadgram threshold.
2. **MEDIUM — vacuous periodicity when `len(known) ≤ key_length`.** If `key_length ≥ m`, then `i % key_length == i` for all i < m and the check passes for **every** rail count — key = entire derived stream, and the plaintext beyond the prefix is unverified guesswork, still reported as found. Same when m < true L: only truncated/wrong keys fit the tried range. Reliable recovery requires `len(known) > true key length` (≥ 2× for period confirmation). State this precondition; optionally flag `key_length == len(known)` as "period unconfirmed."
3. **LOW — keyspace asymmetry.** Known mode hard-gates at `MIN_KEY_LENGTH` (10); frequency mode tries lengths 1–9, which the cipher can never produce. Mostly wasted (flat IC excludes them from the shortlist) but on short/noisy text it can return a `key_length < 10` "winner" that's non-canonical. Note: the wider range *can* legitimately recover correct plaintext via a divisor period, so if intentional, document it.
4. **LOW — IC shortlist (top-8 of 20) is a recall cap**, not a bug: on short ciphertexts the true length may fall outside the top 8 and wrong-rail candidates can outscore the truth. Consistent with the seeded results (0% @100, 35% @200, 95% @400) — worth one sentence in the README, nothing to fix.
5. **INFO — micro-waste:** `QuadgramModel.score` computes `probability` for unknown grams and then discards it in favor of `self.unknown`. Harmless.

One assumption to confirm (it holds per the assignment): encryption order is Vigenère **then** rail-fence, so decryption is rail-fence-first — the code's `stage_one` ordering matches. If the cipher module ever reversed that, both attacks invert silently.
